# final_network — 

The Stage-04 *joined* multimodal transport graph — road + barge (waterway) +
air + seasonal ice road, with every remaining component joined to the giant
network. This folder contains a **frozen handoff**: workflow 02
(`06_export_final_network.py`) writes it, workflow 03
(`01_extract_network_handoff.py` → `02_load_final_network.py`) extracts and
ingests it.

- **Nodes:** `network_joined_nodes.zip` → `network_joined_nodes/…shp` — 84,094 points
- **Edges:** `network_joined_edges.zip` → `network_joined_edges/…shp` — 93,049 lines (synthetic connectors are mode-typed: `{Mode}Connector` welds + per-pair `*Transfer` handoffs)
- **Components:** 4 · **giant:** 99.99% of nodes · **fuel hubs:** 329
- **CRS:** EPSG:3338 — NAD83 / Alaska Albers (meters). The `.prj` reads as `NAD_1983_Alaska_Albers`.

The zips are committed; the extracted shapefiles are gitignored
and regenerated by `workflows/03_multimodal_join/01_extract_network_handoff.py`.

## THE CONTRACT: edge_id = shapefile row order

Workflow 03's stages 02 and 03 (`fuel_network.load`, `fuel_network.weights`) key every
DuckDB table by the **0-based row order of the edges shapefile**. Any change
to these bytes — a re-export, a repack that re-orders rows, even a
"harmless" attribute edit — invalidates `network_edges`,
`edge_month_weights`, and `edge_costs` together. That is why the members are
checksummed below and must stay **byte-identical**.

## The hub handoff: `hub_members.csv` + `hub_snaps.csv`

Written by `06_export_final_network.py` through `mmnet.handoff` beside the zips (and
listed in `MANIFEST.sha256`), from stage 02's `02_hubs.gpkg` + `01_site_members.csv` and
stage 03's `02_hub_snaps.csv`. They say what the shapefiles cannot: which inventory
records each hub serves, the corrected community key it was built for, and where it
landed. A consumer reads them instead of inferring hub membership by distance or a hub's
community by a vote over nearby facility labels.

| File | One row per | Columns |
|---|---|---|
| `hub_members.csv` | (hub, raw inventory record) | `hub_id` (as in `network_joined_nodes.hub_id`), `hub_key` (workflow 00's `community_key`, else the canonical inventory spelling), `hub_community` (display label), `hub_kind` (community · remote_site · blob), `delivery_method`, `hub_type`, `ast_facility_id` (member site; `SYN-<cluster>` when the records carry none), `record_id` (workflow 00's raw record id; empty without the record trail), `node_id` (empty when unplaced), `snap_status` (placed · merged:<hub> · unplaced:beyond_cap) |
| `hub_snaps.csv` | hub | `hub_id`, `node_id`, `snap_dist_m`, `snap_surface`, `status` — stage 03's placement trail, verbatim |

A hub `merged:<other>` shares `<other>`'s node: the node's `hub_id` reads `Hub_a+Hub_b`.
`02_load_final_network.py` loads both files into the DuckDB deliverable as `hub_members`
and `hub_snaps` when they exist (an older export has neither), checking that every placed
hub's node is an `is_hub` node and that the placed hubs land on exactly the shapefile's
hub-node count.

## Field names (Shapefile 10-character limit)

Shapefile/DBF truncates field names to 10 characters, so three long names are
shortened on export. Full mapping:

**Nodes**

| shapefile field | meaning |
|---|---|
| `node_id`    | 0-based node id (matches edge `from`/`to`) |
| `is_hub`     | 1 if a fuel hub snapped to this node |
| `hub_id`     | hub identifier (when `is_hub`) |
| `deliv_meth` | **delivery_method** — the hub's mode(s): Road / Barge / Plane / "… or …" combos |
| `hub_type`   | Supplier / Receiver |
| `hub_cap`    | **total_hub_capacity** — summed fuel capacity at the hub (text in DBF; coerced numeric at ingest) |
| `snap_surf`  | **snap_surface** — surface the hub snapped to (Road / IceRoad) |
| `component`  | connected-component id (1 = the giant) |
| `is_giant`   | 1 if the node is in the giant component |

**Edges**

| shapefile field | meaning |
|---|---|
| `from`, `to` | endpoint `node_id`s |
| `type`       | Road · Waterway · Air · IceRoad · RoadConnector · IceRoadConnector · BargeRoadTransfer · BargeIceRoadTransfer · IceRoadRoadTransfer · AirRoadTransfer · BargeAirTransfer |
| `source`     | provenance (e.g. `Road`, `ports`, `barge_hubs`, `weld:*`, `bridge:*`, `shore:*`, `join:to-giant`) |
| `join_gap_m` | for stage-04 join connectors, the straight-line gap (m) that was closed; NULL/0 otherwise |

Edge-type inventory (the ingest's hard tripwire): Road 55,539 · Waterway
34,178 · Air 226 · IceRoad 1,248 · RoadConnector 1,498 · IceRoadConnector 34 ·
BargeRoadTransfer 289 · BargeIceRoadTransfer 21 · IceRoadRoadTransfer 12 ·
AirRoadTransfer 2 · BargeAirTransfer 2. Synthetic connectors are named by the modes they join
(`{Mode}Connector` welds, per-pair `{A}{B}Transfer` handoffs); `edge_class`
mirrors `type`.
