## Summary

alaska_network_mmnet builds the Alaska bulk-fuel multimodal transport graph (Road + Barge/Waterway + Plane/Air + seasonal Ice Road) with a vendored, region-agnostic `mmnet` Python package plus a bundled R/sfnetworks "oracle". All region specifics live as DATA in profile.yaml; the engine chain is consolidate(01) → tag(01b) → hubs(02) → build(03: R nodes road/ice/air lines, Python nodes the waterway by 50 m vertex rounding, snaps hubs to Road∪IceRoad, snaps airports onto road nodes, adds barge↔road/ice Transfer edges at ports + barge hubs, proximity welds/bridges ≤3 km, a ≤2 km connect-to-giant shore-landing pass) → join(04: straight "Join" connectors for any component within 20 km of the giant, iterated to stability). Stage 03 (`output/03_network__{nodes,edges}.gpkg`, 66 components, ~98.6% giant) stays canonical; Stage 04 (`output/04_network_joined__{nodes,edges}.gpkg`, 21 components, ~99.65% giant, 384 fuel hubs) is the deliverable. `scripts/export_final_shapefile.py` converts the Stage-04 GeoPackages into `final_network/network_joined_{nodes,edges}.shp` (EPSG:3338, DBF-safe renamed fields) — the artifact the sibling friction repo (alaska-fuel-spatial-network, the cwd) ingests as zipped copies via its `load_final_network.py` → fuel_network.duckdb.

Around the engine sit: numbered `scripts/` for data prep (normalize_raw, prep_waterway, prep_airways, fetch_basemap), viz/QGIS exports, and `run_all.sh` as the profile-edit rebuild driver; generated-but-committed per-stage `notebooks/`; `explain/` narrated walkthrough scripts (self-declared disposable yet run_all.sh depends on explain/verify_north_slope.py); eight tracked `research/` sandboxes whose findings were already ported into the engine/profile; and `mmnet-toolkit/`, a second full copy of the package plus skills and an Alaska example, which has drifted from the vendored copy (MMNET_* vs NETWEAVE_* env vars). Git is clean of junk (146 tracked files), but the working tree carries .venv, egg-info dirs, __pycache__ everywhere, an unrelated example_skills/ folder with __MACOSX and .DS_Store, Quarto render junk inside data/interim, and a writing-coach ledger in output/. The main staleness: the air-data story in README/docs still describes the old report-extracted OD CSV and global airports.csv, while the actual inputs are the official flight_paths_combined.csv + airports_ak_dotpf.csv, leaving scripts/extract_od_table.py dead.
