## Summary

alaska-fuel-spatial-network is the public "friction-layer" companion repo for a Data-in-Brief paper. It does three things in sequence: (1) builds an environmental friction stack for Alaska — a static terrain surface (overland.tif), a static NoData-free land-edge surface (road_base.tif), and 12 monthly barge navigability surfaces (barge_MM.tif) — from slope/LULC/permafrost/sea-ice/river-ice rasters on a canonical 150 m EPSG:3338 grid (28,000 x 16,567, anchored to lulc.tif); (2) ingests the delivered multimodal network (82,300 nodes / 90,921 edges, produced by the sibling mmnet repo and shipped as final_network/network_joined_{nodes,edges}.zip) into fuel_network.duckdb at the repo root; (3) samples the friction rasters along every edge geometry (75 m densification, length-weighted mean, strict any-NoData-=>-impassable rule) into edge_month_weights, then joins per-mode $/gallon-mile rates and intermodal transfer fees from friction_surface/friction_costs.py into edge_costs and an nx.MultiGraph with per-month (cost, passable) attributes. The multi-agent routing/TSP layer is explicitly out of scope (stubbed at backfill_facility_edges, blocked on a hub_facility_map table that never gets written here).

Design is clean in the core (friction-vs-cost separation is enforced everywhere; single-source-of-truth config; hard integrity checks against the README-documented network inventory; stable edge_id = shapefile row order shared between ingest and weighting), but the release copy carries drift: docs advertise flags and files that no longer exist, the fee-inference logic is duplicated verbatim in two modules, several friction_costs helpers reference tables/CSVs not shipped in this copy, and the required build_corridor_masks.py step (waterway mask, consumed by the barge surface) is missing from the canonical run order in README.md.

- 0b. (external, ArcGIS Pro arcpy) friction_surface/friction_preprocessing/river_ice_full_pipeline.py — Brown et al. 2026 reach points + NHD masks (from build_brown_polygon_mask.py) -> river_ice_{01..12}.tif; pad_sea_ice_to_grid.py / pad_river_ice_to_grid.py pad exports to the full reference grid
- 0c. python -m friction_surface.friction_preprocessing.align_permafrost — snaps the extent-clipped GEE permafrost export onto the lulc canonical grid (rewrites friction_surface/friction_inputs/permafrost.tif in place)
- 0d. friction_surface/check_grid_exports.py + python -m friction_surface.friction_preflight — metadata-only / full preflight gates: every input matches lulc.tif CRS/transform/shape and value ranges
- 1. python build_corridor_masks.py — rasterizes inputs/data_for_network_build/water_networks/waterways_network_ak_albers.shp (75 m buffer, all_touched) -> outputs/waterway_mask_150m.tif; REQUIRED BEFORE stage 2 or barge surfaces sever ~18% of waterway edges (build degrades with only a warning) — omitted from README's run order
- 2. python -m friction_surface.run_friction_pipeline — reads friction_surface/friction_inputs/{slope,lulc,permafrost}.tif + sea_ice/ + river_ice/ (+ waterway mask); write_friction_stack -> friction_surface/friction_outputs/friction_stack/: overland.tif (slope-class x LULC x permafrost, water=NoData), road_base.tif (max(1.0, slope_friction) x permafrost, NoData-free), barge_{01..12}.tif ((lulc_water | waterway_mask) & ~(sea_ice>0.15 | river_ice>0.15), friction 1.0, blocked=NoData; river ice nearest-filled onto uncovered network cells via cKDTree). 14 files backing 24 logical (mode,month) entries
- 3. python load_final_network.py — reads final_network/network_joined_{nodes,edges}/…​.shp (SIBLING-REPO deliverable; ships only as .zip — manual unzip required, script does NOT extract); validates counts/CRS/topology against final_network/README.md inventory (82,300 nodes, 90,921 edges, 384 hubs, 21 components, giant 99.65%); derives edge_class (Bridge -> Weld / IceRoadWeld); writes network_nodes + network_edges into fuel_network.duckdb (repo root, CREATE OR REPLACE); cross-checks edge_month_weights ids if already present
- 4. python weight_network_edges.py — densifies every edge at 75 m, samples road_base.tif (Road/Join/IceRoad + ice-provenance Bridge welds, x2.0 IceRoad time penalty) and barge_{MM}.tif per month (Waterway); Bridge/Air/Transfer get flat friction 1.0; strict rule: any NoData sample => impassable that month; IceRoad hard-gated to months {1,2,3}; writes edge_month_weights (1,091,052 rows) to fuel_network.duckdb
- 5. python assemble_weighted_graph.py — joins edge_month_weights x network_edges; cost_per_gallon = (length_m/1609.344) x avg_friction x BASELINE_RATES_PER_GALLON_MILE[mode]; Transfer edges priced from INTERMODAL_TRANSFER_FEES keyed by incident line-haul modes (hard error on ambiguity); writes edge_costs (1,091,052 rows) to fuel_network.duckdb; optional --smoke-dijkstra builds the nx.MultiGraph (edge key = edge_id, month_cost dict) and runs hub-to-hub Dijkstra; backfill_facility_edges is a NotImplementedError stub
- 6. Inspection: python run_validation_query.py (monthly passability by mode), python query_duckdb.py (schema/ad-hoc), python make_network_plots.py (3 PNGs to outputs/final_network_plots/ from the shapefiles, not the DB); post-build QA: python -m friction_surface.qa.qa_friction_stack (14-file contract, ice-gating direction, value floor); orchestrated QA chain: .claude/skills/run-friction-pipeline/scripts/validate_friction_stack.py
