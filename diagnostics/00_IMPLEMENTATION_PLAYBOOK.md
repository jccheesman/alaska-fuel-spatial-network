# Implementation playbook — build the merged repo

Self-contained execution guide for a Claude Code session. Target: one public repo
(working name `alaska-fuel-multimodal-network`) with `src/{mmnet,friction_surface}`,
four numbered `workflows/`, a single top-level `inputs/`, and the frozen `final_network/`
handoff. Governing spec: `../MIGRATION_SPEC.md`. Detailed old→new file mapping:
`12_proposal_library_workflows_ADOPTED.md`.

Repo paths on this machine:

- REPO_A = `~/00_academics/99_myresearch/00_myanalysis/02_network_analysis/alaska-fuel-spatial-network`
- REPO_B = `~/00_academics/99_myresearch/00_myanalysis/02_network_analysis/alaska_network_mmnet`

## Guardrails (read before every phase)

- Never commit or push without the owner asking (house rule).
- `final_network` zip **members must stay byte-identical** — record member md5s before any
  repack, verify after. Only `__MACOSX`/`.DS_Store` cruft may be stripped.
- Do not move, rename, or delete the REPO_B working tree — the TAPS study
  (`alaska_network_pipeline_mmnet`) editable-installs mmnet from an absolute path inside it.
  Work in clones.
- `.gitignore` + `.gitattributes` land **before any `git add`** in the merged tree —
  REPO_B's disk carries `.venv/`, `*.egg-info`, `__pycache__`, `__MACOSX`, `.qgz` junk.
- Move-only commits separate from edit commits, so rename detection and blame survive.
- The friction half cannot run end-to-end here (rasters absent) — its edits ship verified
  by unit tests and preflight dry runs only; say so in the final report.

## Phase 0 — owner decisions (ask, don't assume)

archived-with-pointer or renamed; (2) code license + data-redistribution clearance for

for CITATION.cff; (4) freeze (default) vs rebuild the network; (5) repo name.
