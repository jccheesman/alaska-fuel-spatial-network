## Summary

Three divergent copies of the mmnet package exist across the two repos; the newest/canonical code is alaska-fuel-spatial-network/mmnet-toolkit/mmnet (carries 4 bugfixes absent elsewhere), while the copy actually installed and used to build the network (alaska_network_mmnet/mmnet) is the oldest. The final_network handoff is currently byte-in-sync: the two zips in alaska-fuel-spatial-network/final_network contain shapefiles md5-identical to alaska_network_mmnet/final_network (exported Jul 20 by scripts/export_final_shapefile.py from output/04_network_joined). The fuel repo ingests them into fuel_network.duckdb (repo-root relative path, gitignored, not on disk) as network_nodes, network_edges, edge_month_weights, edge_costs; hub_facility_map is planned but has no writer. Main coupling risks: the edge_id=row-order convention shared by two scripts, the Bridge/IceRoad "weld" disambiguation logic duplicated in two files, hard-coded EXPECTED inventory constants, and alaska_network_mmnet having no git remote.

## Issues (ranked)

- The pip-installed / import-resolved mmnet in alaska_network_mmnet (alaska_network_mmnet/mmnet, NETWEAVE_*-era) is the OLDEST of three divergent copies and lacks the fuel repo's bugfixes — notably the assemble.py:34 roads.reset_index(drop=True) mis-snap fix and the io_readers.py nullable-string fix. Rebuilding the network via scripts/run_all.sh runs unfixed code, and the fixes in alaska-fuel-spatial-network/mmnet-toolkit/mmnet have never been backported to the copy that actually built the delivered shapefiles.
- alaska_network_mmnet has no git remote (single local copy of the network-build history, incl. the only regeneration path for final_network); it is also on 'master' while the public repo uses 'main'.
- Bridge-weld/IceRoad disambiguation is sync-by-convention in two places: weight_network_edges.py:252-267 re-implements the str.contains('IceRoad') rule on the raw shapefile instead of reading the edge_class column load_final_network.py:76-88 persists — a rule change in one file silently diverges the other.
- edge_id is defined only as shapefile row order, created independently in load_final_network.py:183 and weight_network_edges.py:319; any re-export from alaska_network_mmnet that reorders rows invalidates edge_month_weights/edge_costs. The cross-check (load_final_network.py:133-151) only verifies the id RANGE (0..n-1), not that weights were computed from the same file content.
- The hard-coded EXPECTED inventory (load_final_network.py:58-73) triples the counts already in final_network/README.md — every re-export requires editing constants in the fuel repo, and the README numbers are not machine-read.
- Cross-repo handoff is manual and undocumented in code: the fuel repo commits zips (with __MACOSX cruft) but its readers expect them pre-extracted into final_network/network_joined_{edges,nodes}/ subdirs; no script performs the copy/zip/unzip between repos.
- profile.yaml is vendored 3x (currently identical); the two mmnet-toolkit trees have no declared canonical home, so future edits will fork the engine further (already 4 files diverged).
