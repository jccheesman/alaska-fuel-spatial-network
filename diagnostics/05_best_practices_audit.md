## Issues (ranked, most severe first)

- 1. NO LICENSE anywhere (both repos, both vendored toolkits). A public repo without a license grants outside researchers no reuse rights at all — blocks the entire purpose of the release. Add one LICENSE at the merged root (plus a data-license note, since committed AEA/Census/USACE-derived zips may carry their own terms).
- 2. Repo 2 (alaska_network_mmnet) is unrunnable from a fresh clone: data/raw/** is gitignored and no tracked file gives download URLs or a fetch script; the provenance MANIFEST.md is generated into gitignored data/interim/. On merge, either extend repo 1's EXTERNAL_DATA.md/inputs zips to cover repo 2's exact data/raw layout referenced by profile.yaml, or add a data-acquisition doc/script.
- 3. Three diverging copies of the mmnet package would coexist in the merged repo (alaska_network_mmnet/mmnet, alaska_network_mmnet/mmnet-toolkit/mmnet, alaska-fuel-spatial-network/mmnet-toolkit/mmnet; config/pipeline/__init__ and assemble/build/config/io_readers differ pairwise) and both pyprojects claim name mmnet v0.1.0 — a cloner cannot tell which is canonical and pip installs are ambiguous. Consolidate to ONE package before publishing.
- 4. No CITATION.cff and no DOI/citation guidance in either repo, for code explicitly accompanying a Data-in-Brief paper.
- 5. Committed notebooks (repo 2 notebooks/0*.ipynb) hard-code /home/diegoarias/... as PROJECT and set env vars from it — they fail verbatim for any cloner. Make build_notebooks.py emit a relative/dynamic root (e.g. Path.cwd() or a .here sentinel) and regenerate.
- 6. No CI in either repo and near-zero tests (one test module in repo 1, none in repo 2, none in either mmnet-toolkit despite a declared pytest extra). A minimal GitHub Actions job (install + pytest + a profile-validate smoke step) would back a reproducibility claim.
- 7. Environment spec fragmentation: four dependency declarations across the merge (requirements.txt, requirements-friction.txt, 2x pyproject), mixed/absent pinning, no lockfile, undeclared imports (nbformat, pyogrio). House style is uv + pyproject + uv.lock; at minimum unify to one spec with one pinned lock for the merged repo.
- 8. No single reproduce-everything command for the merged pipeline: repo 1 requires four manual commands in order; repo 2 has scripts/run_all.sh but only for its half. The merged repo needs ONE documented entry point spanning normalize->build network->friction stack->ingest->weight->assemble.
- 9. Merge collisions: two final_network/ dirs with opposite roles (generated vs ingested), two root READMEs/.gitignores with conflicting ignore regimes (blanket *.zip/*.shp + negations vs data/** patterns — naive concatenation would untrack repo 2's tracked xlsx/CSVs or re-admit repo 1's blobs), and triplicated profile.yaml examples.
- 10. Repo 2 on-disk junk one bad 'git add .' away from the public repo: mmnet.egg-info/ (x2), ~14 __pycache__ dirs, .venv/, example_skills/__MACOSX/, output/*.qgz, .claude/settings.local.json; __MACOSX and example_skills are not in any .gitignore.
- 11. Hardcoded Windows default paths r'E:\DOE\Friction_layer\FRICTION_LAYER' in two ArcGIS preprocessing scripts (env-var overridable and documented, but a cloner hits them first).
- 12. House-style gaps to fix pre-release: no CLAUDE.md lab notebook (pipeline table + Finding column) in either repo; top-level scripts and outputs lack the NN_ numbering / producer-number convention; *.executed.ipynb gitignored contra convention; knobs are plain module constants rather than fenced knobs blocks (repo 1).
